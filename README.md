# EventsApp
Инструмент для создания списка событий

# Особенности
- добавить событие
- удалить
- обновить информаци по событию
- просомтреть список событий
- найти событие по идентификатору
- добавить бронь для события
- найти бронь по идентификатору

# Стек технологий
WebAPI

# Запуск
1. Клонируйте репозиторий
2. Перейдите через компндную строку в ..\EventsApp\EventsWebApplication\EventsWebApplication
3. Выполните команды:
dotnet build - для сборки,
dotnet run - для запуска.

#Запуск тестов
1. Перейдите через компндную строку в ..\EventsApp\EventsWebApplication\EventService.Tests
2. Выполните команду: dotnet test.

# Импользование
Перейдите по ссылке https://localhost:7154/swagger/index.html, перед вами откроется список endpoint-ов

# Endpoints
GET ../Events - Метод возвращает DTO PaginatedResult включающий:
-общее количество событий,
-массив самих событий,
-номер текущей страницы,
-количество элементов на текущей странице.
Входные параметры:
-"title"(string, опциональный) — поиск по названию (регистронезависимый, частичное совпадение);
-"from"(DateTime, опциональный) — события, которые начинаются не раньше указанной даты;
-"to"(DateTime, опциональный) — события, которые заканчиваются не позже указанной даты;
-"page"(int, опциональный, c значением по умолчанию 1) — страница, которую необходимо вернуть;
-"pageSize"(int, опциональный, со значением по умолчанию 10) — количество элементов на странице.

GET ../Events/{id} - Метод возвращает событие по идентификатору из коллекции
-информацию по событию
-404, если событие не найдено

POST ../Events - Метод добавления события в коллекцию:
-201, если событие добавлено
-единообразный JSON-ответ с информацией об ошибке

PUT ../Events/{id} - Метод изменения события
-204, событие изменено
-единообразный JSON-ответ с информацией об ошибке

DELETE ../Events/{id} - Метод удаления события по идентификатору из коллекции
-204, событие удалено
-400, возникли ошибки при удалении

POST ../Events/{id}/book - Метод создания брони по идентификатору события
-404, если событие не найдено
-202, бронь создана и в теле ответа
возвращает информацию о созданной брони (включая Id, EventId, Status)

GET ../Event/booking/{id} - Метод возвращает текущее состояние брони по её идентификатору
-404, если бронь не найдена
-200(с информацией о брони), если бронь найдена

#Формат ответа при ошибках
Возвращается единообразный JSON-ответ с информацией об ошибке:
-код статуса;
-сообщение об ошибке.

# Модель данных(Event)
Id - идентификатор
Title - Название
Description - Описание
StartAt - Начало
EndAt - Окончание

# Модель данных(Booking)
Id - идентификатор брони
EventId - идентификатор события, к которому относится бронь
Status - текущий статус брони
CreatedAt - дата и время создания брони
ProcessedAt - дата и время обработки брони

# Статусы брони(BookingStatusEnum)
Pending - статус у вновь добавленной брони
Confirmed - бронь подтверждена
Rejected - бронь отклонена

# Фоновая обработка
- cервис BookingProcessService периодически опрашивает хранилище на наличие бронирований в статусе Pending;
- для каждой необработанной брони выполняется искусственная задержка;
- после задержки бронь переводится в статус Confirmed;
- после смены статуса заполняется поле ProcessedAt;
- обновлённая бронь сохраняется в хранилище.

# Сценарий использования
- создайте событие через POST ../Events;
- создайте бронь через POST ../Events/{id}/book, где id - идентификатор события;
- сразу запросите GET ../Event/bookings/{id} — статус должен быть Pending;
- подождите несколько секунд и повторите запрос — статус должен измениться на Confirmed.
